# Project Specification: Goal Recognition & Intention Inference in Multi-Agent Environments

## 1. Core Research Objective & Formal Ontology
Given partial behavioral observations of interacting agents in a shared spatial environment, the objective is to infer their hidden terminal goals, decode their latent behavioral intentions, and anticipate their immediate future actions.

### 1.1 Formal Distinction of Key Concepts
To maintain scientific rigor and avoid geometric trivialities, the system strictly distinguishes between five core concepts:

1. **Goal ($G$)**:
   - The terminal objective or destination that an agent seeks to achieve.
   - **Domain**: $G \in \mathcal{G} = \{g_1, g_2, \dots, g_K\}$, where each $g_k \in \mathbb{Z}^2$ is a discrete target landmark; equivalently $G = \text{REACH_TARGET}(T_k)$ for landmark $T_k$.
   - **Visibility**: Hidden variable, known only to the executing agent policy; unobserved by the inference system.

2. **Intention ($I_t$)**:
   - **Authoritative Definition**: *Intention labels are latent policy states generated by the agent's behavioral policy. The policy may use proximity, history, goal progress, environmental state, and other agents when selecting an intention, but intention selection must not be defined by a single deterministic geometric condition. Intention is a short-horizon behavioral strategy used by the agent to pursue its hidden goal.*
   - **Domain**: $I_t \in \mathcal{I} = \{\text{DIRECT}, \text{DETOUR\_LEFT}, \text{DETOUR\_RIGHT}, \text{WAIT}\}$.
   - **Ontology statement**: *Goals are long-horizon spatial objectives. Intentions are short-horizon behavioral strategies used to pursue the currently active goal. Every intention is interpreted conditional on the current goal.* Intentions are subordinate to the goal; there are no agent-relative goals and no agent-following/interception intentions in the active design.
   - **Generative Hierarchy**:
     $$\text{Hidden Goal } G \longrightarrow \text{Agent Policy}(S_t, G, M, \text{Peers}, I_{t-1}, H_{1:t}) \longrightarrow \text{Intention } I_t \longrightarrow \text{Action } A_t \longrightarrow \text{Observation } O_t$$
   - **Intention Persistence**: Intentions exhibit temporal commitment via a minimum dwell time ($D_{\min} \in [3, 5]$ steps, configurable) or stateful hysteresis. The policy cannot instantaneously flip intention purely due to transient geometric jitter.
   - **Stochastic Intention Dynamics**:
     $$P(I_t \mid S_t, G, I_{t-1}) = \operatorname{softmax}\left(U(S_t, G, I_{t-1})\right)$$
     where $U$ denotes the policy utility function incorporating goal progress, peer distance, and persistence bias.

3. **Action ($A_t$)**:
   - An individual observable primitive behavior selected by the agent at a discrete time step.
   - **Domain**: $A_t \in \mathcal{A} = \{\text{UP}, \text{DOWN}, \text{LEFT}, \text{RIGHT}, \text{WAIT}\}$.

4. **Observation ($O_t$)**:
   - The public perceptual state available to an external observer at time step $t$.
   - **Observer Model**: Global structured observer (see Section 4).
   - **Domain**: $O_t = \langle p_{0, t}, A_{0, t-1}, \{p_{j, t}, A_{j, t-1}\}_{j=1}^{N-1}, M, \mathcal{G} \rangle$.
   - **Strict Information Isolation**: Purely observable. Excludes privileged simulator variables (internal costs, planner seeds, hidden goal $G$, latent intention $I_t$, future states).

5. **Trajectory ($\tau_{1:t}$)**:
   - An ordered temporal sequence of observations up to time $t$: $\tau_{1:t} = (O_1, O_2, \dots, O_t)$.

## 2. Updated Formal Probabilistic Formulation

### 2.1 Primary Hierarchical Formulation
The primary hierarchical inference chain is structured as:
1. **Goal Recognition**:
   $$P(G \mid O_{1:t})$$
2. **Latent Intention Inference** (accounting for intention persistence and history):
   $$P(I_t \mid O_{1:t}, G, I_{t-1})$$
3. **Conditioned Next-Action Prediction**:
   $$P(A_{t+1} \mid O_{1:t}, G, I_t)$$

### 2.2 Secondary Marginal Formulation
For unconditioned benchmarking, the marginal next-action distribution is evaluated:
$$P(A_{t+1} \mid O_{1:t}) = \sum_{g \in \mathcal{G}} \sum_{i \in \mathcal{I}} P(A_{t+1} \mid O_{1:t}, G = g, I_t = i) P(I_t = i \mid O_{1:t}, G = g) P(G = g \mid O_{1:t})$$

### 2.3 Bayesian Belief Formulation
The Bayesian baseline maintains a recursive joint belief state over goals and persistent intentions:
$$b_t(G, I_t) \propto P(O_t, A_t \mid S_t, G, I_t) \sum_{I_{t-1}} P(I_t \mid S_t, G, I_{t-1}) b_{t-1}(G, I_{t-1})$$

## 3. Environment Dynamics: 2D Multi-Agent Grid-World

### 3.1 World Parameters
- **Grid Dimensions**: Width $W = 16$, Height $H = 16$ (configurable via YAML).
- **Static Obstacles**: $M \subset \mathbb{Z}^2$, generated with connectivity validation ensuring path feasibility between all starts and goals.
- **Candidate Targets**: Fixed set of $K = 4$ target coordinates $\mathcal{G} = \{g_1, g_2, g_3, g_4\}$.
- **Agent Population**:
  - Focal Agent ($i=0$): Subject of goal recognition and intention inference.
  - Interacting Agents ($j \in \{1, \dots, N-1\}$ with $N \in \{1, 2, 4\}$): Peer agents with distinct stochastic policies.
- **Hidden Goal Assignment** (per episode, not per scenario): the focal agent's goal index is drawn uniformly from the $K$ candidate targets by a dedicated `goal_seed`, independently of the layout and of the start position; peer goals are drawn **independently and uniformly over all $K$ targets** (peers may share a target). Assigning one fixed goal per scenario would make $P(G \mid O_{1:t})$ degenerate (a constant label), which is asserted against in `tests/test_dataset.py::test_hidden_goal_varies_across_episodes`. Independence of the *peer* draws is a validity requirement for RQ2, not a convenience: under sampling without replacement, an observer that recovers the peers' goals from their trajectories can recover the focal goal by elimination — exactly, once $N = K$ — so the interaction-visible arm would win by counting instead of by explaining peer-induced perturbations. `tests/test_dataset.py::test_peer_goals_carry_no_information_about_the_focal_goal` pins the resulting 1/K sharing rate.
- **Peer Spawn Locality**: peer agents spawn within `peer_spawn_radius` cells of the focal agent when the layout allows it, so agents share corridors and the symmetric collision / blocking mechanics actually fire (needed for RQ2).

### 3.2 Symmetric Collision Resolution (Zero Agent-ID Priority)
Single-pass simultaneous transition rule. No agent-ID priority, no sequential update, no fixed-point iteration.

At timestep $t$, every agent selects an `intended_action`. Each proposal destination is $d_i = p_i + \Delta(A^{\text{intent}}_{i,t})$. A proposal is valid only if:

- $d_i$ is inside the grid bounds;
- $d_i$ is not a static obstacle;
- $d_i$ is not occupied at time $t$;
- no other agent proposes the same destination.

Formally:

$$\text{move}_i = \mathbb{1}\big[d_i \notin M,\ d_i \in \text{Bounds},\ d_i \notin \text{Occupied}_t,\ |\{j: d_j = d_i\}| = 1\big]$$

Valid proposals move simultaneously. All invalid proposals leave their agents in their original cells. Movement decisions never depend on agent ID.

**Documented consequences:**
- **Same destination** (`A→X`, `B→X`): both remain (occupancy/uniqueness check fails).
- **Swap** (`A: X→Y`, `B: Y→X`): both remain, because both destinations are occupied at time $t$.
- **Rotation cycles** (`A: X→Y`, `B: Y→Z`, `C: Z→X`): all remain, because every proposed destination is occupied at time $t$. Longer cycles behave identically: all agents remain.
  - *Note (verified, `tests/test_environment.py`)*: on a 4-connected grid a 3-cycle cannot occur. Colouring a cell by $(x+y) \bmod 2$ makes the grid graph bipartite, so it contains no odd cycle; a rotation in which every proposed destination is occupied therefore needs an even number of agents. The smallest realizable case is the 4-cycle, which is what the test suite exercises (4- and 6-agent rotations).
- **Convoy** (`A: X→Y`, `B: W→X`): $B$ cannot move because $X$ is occupied at time $t$; no iterative re-check is performed, so convoy movement is staggered. This is intentional.
- **Obstacle/boundary**: agent remains in place.

### 3.3 Persistent Blocking Policy Mechanism
To avoid perpetual deadlocks under symmetric rules, agents handle blocking at the **policy level**:
- If an agent is blocked for $k_{\text{blocked}} \ge 2$ consecutive steps:
  - The policy elevates the utility of detour-related intentions (`DETOUR_LEFT` or `DETOUR_RIGHT`).
  - This guarantees natural, emergent intention transitions without compromising environment symmetry.

### 3.4 Termination Conditions
1. `GOAL_REACHED`: Focal agent enters its assigned goal cell $p_0 = G$.
2. `MAX_STEPS`: Episode horizon exceeds $T_{\max} = 50$.
3. `DEADLOCK_LIMIT`: All active agents remain mutually blocked for $> 10$ steps.

## 4. Formal Observer Model & Information Isolation

### 4.1 Observer Classification
- **Type**: Global structured observer.
- **Map & Target Visibility**: Full observability of static map geometry $M$ and candidate target locations $\mathcal{G}$.
- **Agent Visibility**: Observer perceives positions and realized-action histories of the focal agent and all active peer agents (Condition A).
- **Condition consistency**: The observer model is identical between experimental conditions except for the interaction-information mask (`interaction_mask`). Hidden variables are: focal goal, focal intention, future state, future action, intended actions, privileged simulator variables.
- **Policy sensing ≠ observer visibility**: `policy_sensing_radius` may exist as an agent-policy parameter (how an agent decides to react to nearby peers), but it never determines what the research observer sees. Observer visibility is global; there is no `sensing_radius` or `r_occlusion` in the observation model.

### 4.1a Intended vs. Realized Actions

- `intended_action`: the action selected by the agent policy before the environment transition. Privileged; never observable.
- `realized_action`: the action actually effected by the simultaneous transition (destination valid, or blocked/blocked-by-peer). Observable.
- `blocked`: boolean indicating intended movement did not move the agent due to obstacle, boundary, same-destination, swap, cycle, or convoy conflict. Observable in Condition A only; excluded in Condition B because it can reveal peer interaction.
- `position_before`: the cell the agent occupied when the intention/action for that step was chosen, i.e. the position that is actually observable *before* $I_t$ is generated. Recorded at every step so that $t=0$ exposes the true start cell (the post-transition `position` of step 0 does not).
- `blocked_reason` $\in$ {none, obstacle, boundary, occupied, conflict}: **privileged diagnostic**. It is derived from the intended action and is used only for the Section 6 blocked-step attribution statistics; it never appears in a Condition A or Condition B observation.

The future-action prediction target is the realized action: $A_{t+1} = A^{\text{realized}}_{t+1}$. Intention inference and future-action prediction must use this realized-action definition consistently across PROJECT_SPEC, DATASET_SCHEMA, trajectory serialization, interaction masking, and model inputs.

### 4.2 Observable vs. Privileged State Definition

```text
========================================================================
OBSERVABLE SCHEMA (Public to Models & Evaluator)
------------------------------------------------------------------------
- scenario_id             : str
- grid_dimensions         : [int, int]
- static_obstacles        : list[[int, int]]
- candidate_targets       : list[{"target_id": int, "position": [int, int]}]
- focal_trajectory        : list[{"step": int, "position": [int, int], "position_before": [int, int], "realized_action": str, "blocked": bool}]
- peer_agents_trajectory  : list[{"agent_id": int, "step": int, "position": [int, int], "position_before": [int, int], "realized_action": str}]
- interaction_mask        : bool (controls Condition A vs Condition B)

========================================================================
PRIVILEGED SCHEMA (Strictly Quarantined to Simulator & Evaluation Metric Ground-Truth)
------------------------------------------------------------------------
- focal_goal_id           : int  (Target ground truth G*)
- focal_intention_history : list[str] (Latent intention ground truth I_t*)
- intended_action_history : list[str] (Per-step privileged intended actions)
- planner_internal_state  : dict (utility values, detour flags, heuristic costs)
- seed_state              : int / dict (RNG seeds)
========================================================================
```

### 4.3 Runtime Enforcement
Data loaders and models enforce strict isolation:
```python
OBSERVABLE_KEYS = {
    "scenario_id", "grid_dimensions", "static_obstacles",
    "candidate_targets", "focal_trajectory", "peer_trajectories", "interaction_mask"
}
def validate_batch(batch: dict):
    forbidden = set(batch.keys()) - OBSERVABLE_KEYS
    if forbidden:
        raise SecurityError(f"Privileged information leakage detected: {forbidden}")
```

## 5. M2 Intention Triviality Gate Test
Before accepting the environment implementation in Milestone 2:
1. Train a **shallow single-step classifier** (e.g., Logistic Regression or shallow Decision Tree) taking **only current single-step observable state** ($p_{0, t}$, realized velocity, current cell-local features). Input must exclude peer history, intention history, goal, future steps, and simulator internals.
2. The classifier has **zero access** to past history, future steps, hidden goals, or simulator internals.
3. Evaluate on a **held-out scenario split** and report accuracy and macro-F1.
4. Compare against: (1) majority-class baseline; (2) the shallow single-step classifier; (3) a history-aware reference model, on the same held-out scenarios.
5. **Relative interpretation (no arbitrary universal threshold)**: If the shallow current-state classifier performs approximately as well as the history-aware model (and well above the majority baseline), the intention generator is considered insufficiently non-trivial and must be redesigned. Do not assert a fixed ">75%" cutoff without this comparison.
